# 节点 3/5：CST716 触摸轮询与 EXTI 验收

节点 3 使用旧工程中已验证的 CST716 协议，但将驱动独立放入新工程：

- `Core/Src/cst716.c`
- `Core/Inc/cst716.h`

## 接口合同

```text
SCL  PB0
SDA  PF11（软件 I2C，读写阶段切换 GPIO 方向）
INT  PB1（节点 5 配置为双边沿 EXTI，仅用于唤醒任务）
RESET PC13，低电平复位
写地址 0x2A，读地址 0x2B（8 位总线字节值）
```

驱动复用了旧工程确认的寄存器：触摸点数 `0x02`，第一点坐标 `0x03`，版本 `0xA1`，设备 ID `0xA7`。第一版只读取第一个触摸点，不做校准，也不写入外部 Flash/EEPROM。

当前实机读到的版本字段为 `0x0000`。由于设备 ID 读取、坐标读取和触摸事件均正常，本节点不把该字段强制判定为失败；后续若要做严格芯片识别，应依据 CST716 数据手册确认版本寄存器和期望值。

## 串口验收

初始化成功时应看到：

```text
[TP] CST716 init OK version=0x.... exti=both+poll
```

手指按下屏幕时，USART1 应出现一条：

```text
touch press x=... y=... fingers=1
```

抬起时应出现：

```text
touch release
```

节点 3 中触摸轮询发生在 `ui_task`，周期约 50 ms。节点 5 增加 PB1 双边沿 EXTI：中断服务函数只清除中断并通知 `ui_task`，不在 ISR 中执行软件 I2C；任务收到通知后立即读取一次，同时保留 50 ms 超时轮询，用于补偿丢失或抖动的边沿并检测释放。

健康日志中的 `tirq` 是 PB1 EXTI 边沿计数。它只能证明中断线产生了边沿，触摸坐标仍必须由任务上下文读取和校验。

## 节点 5 实机验收

- 连续点击 5 次，应得到 5 次 `touch press` 和 5 次 `touch release`；
- 长按只产生一组按下/释放；
- 静止时不持续产生触摸事件；
- 竖屏坐标满足 `0 <= x < 480`、`0 <= y < 800`；
- `health bits=0x07`、`qdrop=0`、`supervisor=ok`、`wd=ok` 持续稳定；
- `tirq` 在触摸操作期间增加，且不会无触摸时高速增长。

## 节点 3/5 通过条件

- 启动日志出现 CST716 初始化成功和版本号；
- 静止屏幕时不持续刷触摸日志；
- 每次按下/抬起各产生一条事件；
- 坐标在当前 LCD 方向的有效范围内；
- 原有 `health bits=0x07`、heap、栈高水位和 IWDG 监督继续稳定。
